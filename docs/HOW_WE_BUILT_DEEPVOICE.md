# 딥보이스(AI 음성)를 어떻게 만들었나 — 경진대회 Q&A 대비

> 교수님 질문 **"이 AI 목소리는 어떻게 만들었나요?"** 에 답하기 위한 문서.
> 모델 구조 자체의 원리는 [`GPT_SOVITS_DEEPVOICE_EXPLANATION.md`](GPT_SOVITS_DEEPVOICE_EXPLANATION.md) 참조.
> 이 문서는 **우리가 실제로 거친 제작 파이프라인**(데이터 수집 → 학습 → 합성)에 초점을 둔다.

---

## 0. 30초 핵심 답변 (질문 받으면 바로)

> 공개된 방송·강연 영상에서 전현무 화자의 목소리만 자동으로 추출해 **약 37분 분량(532개 클립)의 학습 데이터셋**을 만들고, 오픈소스 음성 합성 모델인 **GPT-SoVITS**를 그 데이터로 **파인튜닝**했습니다.
>
> 데이터를 만들 때 ① Demucs로 배경음악을 제거하고 ② Silero VAD로 발화 구간만 잘라낸 뒤 ③ ECAPA 화자 임베딩으로 전현무 목소리만 골라내고 ④ Whisper로 자동 전사해서 텍스트 라벨을 붙였습니다.
>
> 학습은 GPU(RTX 4080)가 있는 Windows에서, 합성(추론)은 Mac에서 했습니다. 합성 단계에서 보이스피싱 시나리오 대본을 입력하면 전현무 목소리로 읽어주는 음성이 나오고, 이게 우리 탐지 모델(AASIST)이 **딥보이스로 잡아내야 하는 공격 샘플**이 됩니다.

---

## 1. 무엇을, 왜 만들었나

- **무엇**: 특정 공인(전현무)의 목소리를 모사하는 음성 합성(voice cloning) 모델과, 그 모델로 만든 보이스피싱 시나리오 음성.
- **왜**: 우리 프로젝트는 **딥보이스(AI 합성 음성) 탐지** 시스템이다. 탐지기를 제대로 검증하려면 "실제 공격자가 만들 법한 고품질 사칭 음성"이 필요하다. 시중 단순 TTS 음성만으로는 현실적인 위협을 재현하기 어렵기 때문에, **공격자 관점의 음성을 직접 재현**해서 탐지기가 이를 잡아내는지 시연한다.
- **결과물의 위치**: 합성된 전현무 보이스피싱 음성은 안드로이드 데모의 **탐지 타깃**으로 들어간다. 통화가 재생되면 AASIST 모델이 실시간으로 WARNING/DANGER 등급을 띄운다.

---

## 2. 어떤 모델을 사용했나

**GPT-SoVITS** (오픈소스, RVC-Boss/GPT-SoVITS). few-shot voice cloning이 가능한 2단계 TTS 모델.

- **GPT (s1, text-to-semantic)**: 텍스트를 말소리의 중간 표현인 *semantic token*으로 예측.
- **SoVITS (s2, VITS 계열)**: semantic token + 참조 음성 특징 → 실제 음성 파형 복원.
- 짧은 참조 음성만으로도 화자 음색을 반영(zero-shot)하고, **소량 데이터로 파인튜닝하면 유사도와 안정성이 크게 향상**(few-shot)된다.

> 모델 내부 구조의 상세 설명은 별도 문서 [`GPT_SOVITS_DEEPVOICE_EXPLANATION.md`](GPT_SOVITS_DEEPVOICE_EXPLANATION.md) 에 정리되어 있다.

## 3. 전체 파이프라인 한눈에

```text
[Phase A · 데이터 제작 — Mac M4 Pro]
 공개 방송/강연 영상(m4a) 112개
   └─ ① ffmpeg 디코드 (m4a → PCM)
   └─ ② Demucs(htdemucs) 보컬 분리        → 배경음악·효과음 제거, 목소리만
   └─ ③ Silero VAD 발화 분할              → 말하는 구간만 클립으로
   └─ ④ ECAPA / Resemblyzer 화자 임베딩    → 전현무 목소리만 선별
   └─ ⑤ 사람이 미리듣기 검수(reject)        → 잘못 섞인 화자 제거
   └─ ⑥ Whisper 자동 전사                  → 클립마다 텍스트 라벨
        ▼
   전현무 학습 데이터셋: 532클립 / 약 37.3분 / 32kHz  (jhm.list)

[Phase B · 파인튜닝 — Windows RTX 4080 Super (CUDA)]
   └─ S2(SoVITS) 파인튜닝 + S1(GPT) 파인튜닝
   └─ 에폭별 그리드 학습 후 청취 평가로 베스트 선정
        ▼
   베스트 가중치:  SoVITS jhm_e24_s1152.pth   +   GPT jhm-e30.ckpt

[Phase C · 합성/추론 — Mac M4 Pro (CPU)]
   └─ 참조 음성(jhm_0234.wav) + 보이스피싱 대본 입력
   └─ top_k=5, top_p=1.0, temperature=1.0, 50자 컷 분할
        ▼
   전현무 목소리의 보이스피싱 통화 음성(.wav)  →  데모의 탐지 타깃
```

## 4. 단계별 상세

### Phase A — 학습 데이터 제작 (Mac)

음성 합성 모델은 깨끗한 단일 화자 음성 + 정확한 텍스트 라벨이 필요하다. 방송 영상은 BGM·다중 화자·잡음이 섞여 있어 **그대로 쓸 수 없으므로**, 다음 자동 파이프라인으로 정제했다. (`voicebox-clone-workspace/jhm/`, `build_gptsovits_dataset.py`)

| 단계 | 도구 | 하는 일 |
|---|---|---|
| ① 디코드 | ffmpeg | m4a 등 임의 컨테이너 → float32 PCM (stereo, 44.1kHz) |
| ② 보컬 분리 | **Demucs (htdemucs)** | 음악·효과음 등 반주를 제거하고 사람 목소리만 분리 |
| ③ 발화 분할 | **Silero VAD** | 말하는 구간만 클립으로 분리 (700ms~15s, 무음 제거) |
| ④ 화자 선별 | **ECAPA-TDNN** / Resemblyzer | 발화별 화자 임베딩 → 전현무 음성만 채택 |
| ⑤ 검수 | 사람(montage 미리듣기) | 잘못 섞인 다른 화자 세그먼트 수동 제외 |
| ⑥ 전사 | **Whisper** | 채택된 클립마다 텍스트 라벨 생성 → `jhm.list` |

**④ 화자 선별 두 가지 방식**
- **앵커 방식**: 전현무 단독 발화 몇 개를 평균낸 기준 임베딩(anchor)을 만들고, 각 발화와의 **코사인 유사도가 임계값 이상**인 것만 채택.
- **클러스터 방식(최종 채택)**: ECAPA 임베딩을 agglomerative 클러스터링(거리임계 `dt=0.5`)으로 묶고, **가장 분량이 많은 클러스터 = 전현무**로 보고 채택. 강연·토크처럼 전현무가 주로 말하는 소스에서 안정적. (빠른 컷 예능은 화자 혼입이 심해 데이터 소스에서 제외)

> **핵심 메시지**: "유튜브에서 음성을 그냥 긁어온 게 아니라, **보컬 분리 → 발화 분할 → 화자 식별 → 사람 검수 → 자동 전사**의 다단계 자동 정제 파이프라인을 직접 구현해서 깨끗한 학습 데이터셋을 만들었다."

**최종 데이터셋**: 532개 세그먼트 / 약 37.3분 / 32kHz mono. 라벨 형식 `상대경로|jhm|ko|전사텍스트`.

### Phase B — GPT-SoVITS 파인튜닝 (Windows)

- **왜 Windows인가**: GPT-SoVITS 학습은 CUDA(NVIDIA GPU)가 필요하다. Mac의 MPS는 학습 경로가 지원되지 않아 사실상 CPU-only → 비현실적. 그래서 학습만 RTX 4080 Super가 있는 Windows에서 수행했다. (셋업 절차: `docs/WINDOWS_GPT_SOVITS_SETUP.md`)
- **2단계 학습**:
  - **S2 (SoVITS)**: semantic token → 음성 파형 복원 모델을 전현무 음색에 맞게 파인튜닝.
  - **S1 (GPT)**: 텍스트 → semantic token 예측 모델을 전현무 발화 패턴에 맞게 파인튜닝.
- **에폭 그리드 + 청취 평가**: 여러 에폭의 체크포인트를 만들어 직접 들어보고 가장 자연스럽고 유사도 높은 조합을 골랐다. ECAPA 유사도 점수와 실제 청감이 항상 일치하진 않아 **사람 귀로 최종 선택**.
  - 베스트: **SoVITS `jhm_e24_s1152`(24 epoch)** + **GPT `jhm-e30`(30 epoch)**.

### Phase C — 합성/추론 (Mac)

학습된 가중치를 Mac으로 가져와 추론만 수행(추론은 CPU로 가능, 학습 불가). (`GPT-SoVITS/gen_jeonhyunmoo_vishing.py`, `MAC_INFERENCE.md`)

- **참조 음성(prompt)**: `jhm_0234.wav` + 그 전사 텍스트 → "이런 음색·톤으로 말하라"는 조건.
- **샘플링 설정**: `top_k=5`, `top_p=1.0`, `temperature=1.0`, **50자 단위 문장 컷 분할**(긴 문장 안정화), 숫자는 한글로 표기(발음 안정).
- **시나리오 대본**: 방송 촬영 협조를 빙자해 "보증 보험료 선입금"을 유도하는 보이스피싱 통화 4턴을 작성 → 턴별로 합성 → 0.6초 간격으로 이어붙여 전체 통화 음성 완성.
- **산출물**: `outputs/jhm/jeonhyunmoo_vishing_v4/...` → 안드로이드 데모의 탐지 타깃 음원으로 사용.

## 6. 왜 이렇게 설계했나 (의사결정 포인트)

- **왜 시중 TTS가 아니라 voice cloning인가**: 탐지기가 막아야 하는 현실적 위협은 "특정 인물을 사칭한 음성"이다. 단순 기계음 TTS보다 **특정 화자를 모사한 합성음**이 훨씬 현실적인 공격 시나리오이고, 탐지 난이도도 높다.
- **왜 데이터 정제 파이프라인을 직접 만들었나**: 방송 음성은 BGM·다화자·잡음 때문에 그대로는 학습 불가. 품질 낮은 데이터로 학습하면 합성 품질도 떨어진다(garbage-in-garbage-out). 그래서 **자동 정제 + 사람 검수**를 결합했다.
- **왜 학습은 Windows, 추론은 Mac인가**: 학습은 CUDA 필수(Mac MPS 미지원), 추론은 CPU로도 충분. 역할 분담으로 두 머신을 효율적으로 사용.
- **왜 에폭을 귀로 골랐나**: 화자 유사도 수치(ECAPA)와 실제 청감 자연스러움이 1:1로 일치하지 않아, 정량 점수로 후보를 좁히되 **최종 선택은 청취 평가**로 했다.

---

## 7. 탐지기와의 연결 (이 음성을 왜 만들었는지의 마무리)

- 만든 전현무 합성 음성은 **공격(빨간 팀) 샘플**이고, 우리 시스템의 핵심은 이를 잡아내는 **AASIST 딥보이스 탐지 모델**이다.
- 데모에서 이 음성을 재생하면 탐지기가 실시간으로 딥보이스 점수를 올려 WARNING/DANGER 등급을 표시한다.
- 즉, **"이런 고품질 사칭 음성을 누구나 만들 수 있는 시대 → 그래서 실시간 딥보이스 탐지가 필요하다"** 는 프로젝트 동기를 직접 시연으로 증명하는 장치다.

---

## 8. 윤리·법적 고려 (질문 대비 필수)

- **목적 한정**: 딥보이스 **탐지 연구 및 경진대회 시연** 목적으로만 제작. 실제 사기·기만·금전 요구에 사용하지 않는다.
- **데이터 출처**: 공개된 방송/강연 영상에서 추출. 상업적 재배포·재학습 데이터로 외부 공개하지 않는다.
- **비공개 원칙**: 학습 가중치와 합성 음성은 **공개 저장소에 업로드하지 않으며**, 프로젝트 내부 연구·시연 범위로 제한한다. (전현무는 공인 → 사적 연구 한정)
- **시연 시 고지**: 데모에서 해당 음성이 **AI 합성물**임을 명확히 밝히고, 탐지 대상 예시로만 제시한다.
- **방어적 활용**: 이 작업의 최종 산출물은 "사칭 음성"이 아니라 **그것을 막는 탐지기**다. 공격 샘플 제작은 방어 성능 검증을 위한 수단이다.

## 9. 예상 질문 & 모범 답변 (Q&A)

**Q. AI 목소리는 어떻게 만들었나요?**
A. 공개 방송 영상에서 전현무 목소리만 자동 추출해 약 37분짜리 데이터셋을 만들고, 오픈소스 음성 합성 모델 GPT-SoVITS를 그 데이터로 파인튜닝했습니다. 그 모델에 보이스피싱 대본을 입력해 전현무 목소리로 읽는 음성을 합성했습니다.

**Q. 데이터는 어디서 구했나요? 저작권/초상권 문제는요?**
A. 공개된 방송·강연 영상에서 추출했고, **탐지 연구·시연 목적으로만** 사용합니다. 합성물과 가중치는 외부에 공개·배포하지 않으며, 데모에서 AI 합성음임을 명시합니다. 산출물의 목적은 사칭이 아니라 이를 막는 탐지기 검증입니다.

**Q. 데이터를 그냥 유튜브에서 긁은 건가요?**
A. 아닙니다. 원본 영상은 배경음악·다른 출연자·잡음이 섞여 있어 그대로 못 씁니다. **Demucs로 반주 제거 → Silero VAD로 발화 구간 분리 → ECAPA 화자 임베딩으로 전현무 목소리만 선별 → 사람이 검수 → Whisper로 자동 전사**하는 다단계 정제 파이프라인을 직접 구현했습니다.

**Q. 전현무 목소리인지 어떻게 골라냈나요?**
A. 각 발화를 화자 임베딩(ECAPA-TDNN)으로 벡터화한 뒤, 클러스터링으로 묶어 **가장 분량이 많은 클러스터를 전현무로 채택**했습니다. 보조로 전현무 단독 발화 기준 임베딩과의 코사인 유사도 임계도 활용했고, 마지막엔 사람이 직접 들어보고 잘못 섞인 화자를 제외했습니다.

**Q. 데이터가 얼마나 필요한가요? 왜 37분이면 되나요?**
A. GPT-SoVITS는 few-shot 방식이라 수십 분 분량으로도 화자 유사도를 충분히 끌어올릴 수 있습니다. 짧은 참조 음성만으로도 음색을 반영(zero-shot)하지만, 37분으로 파인튜닝해 안정성과 유사도를 높였습니다.

**Q. 왜 컴퓨터를 두 대 썼나요?**
A. 학습은 NVIDIA GPU(CUDA)가 필요해 RTX 4080이 있는 Windows에서 했고, 합성(추론)은 연산이 가벼워 Mac에서 CPU로 처리했습니다.

**Q. 모델이 직접 만든 건가요, 가져온 건가요?**
A. 모델 아키텍처는 오픈소스 GPT-SoVITS를 사용했고, 우리가 한 것은 **① 학습 데이터셋을 만드는 정제 파이프라인 구현, ② 전현무 화자로의 파인튜닝, ③ 보이스피싱 시나리오 합성**입니다.

**Q. 품질을 어떻게 보장했나요?**
A. 에폭별 체크포인트를 여러 개 만들어 화자 유사도 점수로 후보를 좁힌 뒤, 최종은 직접 청취 평가로 가장 자연스러운 조합(SoVITS 24epoch + GPT 30epoch)을 골랐습니다. 긴 문장은 50자 단위로 잘라 발음 안정성을 확보했습니다.

**Q. 이게 탐지랑 무슨 상관인가요?**
A. 이 음성은 우리 탐지 모델(AASIST)이 잡아내야 하는 **공격 샘플**입니다. 데모에서 이 음성을 재생하면 탐지기가 실시간으로 딥보이스로 분류해 경고를 띄웁니다. 즉, 위협을 직접 재현해 방어 성능을 시연으로 증명합니다.

## 10. 발표용 한 문장 요약

> 공개 방송 영상에서 전현무 목소리만 자동 정제해 만든 약 37분짜리 데이터셋으로 오픈소스 음성합성 모델 GPT-SoVITS를 파인튜닝했고, 거기에 보이스피싱 대본을 입력해 사칭 통화 음성을 만들었습니다. 이 음성은 우리 딥보이스 탐지기가 실시간으로 잡아내야 하는 공격 샘플이며, "이런 사칭 음성을 쉽게 만들 수 있는 시대라 실시간 탐지가 필요하다"는 프로젝트의 동기를 직접 증명합니다.
